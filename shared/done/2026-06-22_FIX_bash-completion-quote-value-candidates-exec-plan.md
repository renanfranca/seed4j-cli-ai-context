# Fix Bash Completion Value Quoting

This ExecPlan is a living document. Keep `Progress`, `Decisions`, `Risks`, and `Lessons Learned` up to date as work advances.

## Purpose / Big Picture

Bash completion currently suggests module option values with spaces, such as `Seed4J Sample Application`, as one `COMPREPLY` item, but Bash inserts the text without shell quoting. A user who accepts that suggestion and runs the command gets unmatched arguments. This plan fixes completion so the accepted suggestion is executable, for example `--project-name "Seed4J Sample Application"`.

## Scope

In scope: Bash completion value candidates generated by `seed4j completion bash`, tests that simulate Bash completion behavior, and documentation examples.

Out of scope: command parsing, module metadata values, non-Bash shells, filesystem path completion, and project history completion.

## Definitions

`COMPREPLY` is the Bash array filled by a completion function. Bash inserts selected entries from it into the current command line.

A value candidate is a static value offered for an option argument, such as `npm`, `pnpm`, or `Seed4J Sample Application`.

Shell quoting means rendering a candidate so Bash treats it as one argument when the user executes the completed line.

## Existing Context

`src/main/java/com/seed4j/cli/command/infrastructure/primary/BashCompletionScriptGenerator.java` generates the Bash function used by `seed4j completion bash`. It collects command, option, and option value candidates from picocli metadata.

`src/test/java/com/seed4j/cli/command/infrastructure/primary/BashCompletionScriptGeneratorTest.java` writes the generated script to a temporary file, sources it from Bash, sets `COMP_WORDS`, invokes `_seed4j_completion`, and asserts `COMPREPLY`.

The current tests assert that `Seed4J Sample Application` is returned as one raw suggestion, which does not prove the accepted command line is executable.

## Desired End State

When completion suggests a value containing spaces or shell-sensitive characters, accepting the suggestion inserts a safely quoted argument. Simple values remain unquoted. Documentation shows the quoted project-name example.

## Decisions

- Decision: Keep module candidate metadata as raw values and apply shell quoting only in the generated Bash script.
  Rationale: Module metadata should not embed shell syntax; quoting is a shell adapter concern.
  Date/Author: 2026-06-22 / Codex

## Risks and Mitigations

- Risk: Tests that only inspect `COMPREPLY` can miss readline insertion behavior.
  Mitigation: Keep tests at the Bash-script boundary and model Bash-realistic `COMP_WORDS` for equals-form completion.

- Risk: Quoting all candidates could degrade simple suggestions such as `npm`.
  Mitigation: Quote only candidates that need shell protection.

## Validation Strategy

1. Run `./mvnw -Dtest=BashCompletionScriptGeneratorTest test` after each TDD cycle.
2. Run `./mvnw -Dtest=BashCompletionScriptGeneratorTest,Seed4JCommandsFactoryTest,BashCompletionInstallationCommandsTest test` after docs/script behavior updates.
3. Ask the user to run `./mvnw clean verify` locally for the full repository gate.

## Rollout and Recovery

The change is local to generated Bash completion output. To recover, revert the completion generator, tests, and docs changes. Users must regenerate or reinstall completion scripts with `seed4j completion bash --install` to receive the fix.

## Lessons Learned

- Milestone 1 showed the existing tests asserted raw COMPREPLY values; updating the behavior contract made the raw-value bug visible.
- Bash presents equals-form completion as separate COMP_WORDS entries around =, so the script must recover the option name from neighboring words.
- Focused completion suite and Prettier check passed on 2026-06-22.
